原书 EPUBCheck 分别有 2、36 个 ERROR；阅读器能打开与打包规范存在局部缺陷可以同时成立。判断翻译是否能够进行，应结合可读正文和可恢复资源，而非只看原书格式错误数。

## 当前处理规则

- `.html/.xhtml/.htm` 唯一同名匹配优先恢复真实文件并修正链接，不生成替代正文。
- 部分图片缺失：使用明确“原文件缺少此图片”的说明图；已存在图片保持其原始二进制数据。
- 样式缺失：回退阅读器默认样式；已存在但未声明的图片、CSS、链接正文补齐 manifest 后保留。
- nav/NCX 缺失：按已有阅读顺序重建；有效 nav 可替代过期 NCX，避免把废弃 NCX 链接误当缺章。
- 真的缺少部分章节：仅插入固定的缺章说明，保留目录目标；说明页不作为译文、不进入模型请求或翻译段落统计。现存正文不会被覆盖。
- ZIP/OPF 损坏、路径越界、超出解包限制、没有实际可读内容以及当前无法安全恢复的资源依赖仍明确拒绝。

上传校验在内存只读视图上验证修复计划；解包器将同一计划应用到临时副本。原始上传文件保持原样。原书警告在付款前、任务详情、批量每本、完成消息和 QA 中保留，重试不会清除。局部原书问题标为 warning；模型翻译失败和最终 EPUBCheck 失败仍按实际错误处理。

## 完整书回归额外发现并修复

1. Python 的 HTML 兼容分支会把 `xmlns` 普通属性再复制到已有命名空间的根元素，造成重复声明。现在保留有效命名空间，避免写出不可解析 XML。
2. ebooklib 0.18 自动页码目录不仅使用 pagebreak，还使用任意带 `epub:type` 与 `id` 的节点。现存辅助目录必须作为 `linear=no` 条目加入 spine；保持原正文阅读顺序。
3. 排版清洗原先会把代码里的 `...`、`--` 改为排版标点。现在保护 `pre/code/kbd/samp/tt`（含嵌套语法高亮），正文仍做正常繁简和排版；横排规则只作用于真正 CSS，不改代码或其他属性内的 CSS 示例。
