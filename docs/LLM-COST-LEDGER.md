# EPUB 模型用量与费用账本

## 统计口径

从本版本开始，翻译费用以模型请求账本为准，不再把默认模型的整本 Token 乘一个固定单价。

- **翻译前报价**仍是估计，不是实际模型成本。
- **价目计算成本**：模型返回的实际 `usage` × 本次留存的供应商/模型价目。可以精确计算已知部分，但并不等于实际余额扣减或充值现金支出。
- **账单导入金额**：人工核对供应商原始账单后，按供应商响应 ID 精确匹配导入。系统不会伪造已确认账单，也不通过反推余额给多本并发图书摊费用。
- 未返回用量、网络超时、进程被强制终止、未知价目、跨计价边界、历史未记录尝试均标记待核实，**不是免费**。
- CNY、USD 等币种分别累计，不使用固定汇率相加。

`coverage=complete` 表示截至当前记录的请求用量/价目及历史覆盖完整，不等于翻译已结束。运行中费用还会增加；全书最终费用必须同时检查任务终态。

## 请求覆盖与写入时机

正式任务通过 `job_runner` 为当前书与翻译 attempt 建立上下文；支付前预分析在工作线程中使用已分配的 `job_id`，归入 `preflight`。章节 Celery 入口也显式携带图书身份。上下文通过 `ContextVar` 隔离异步节点与并行图书。

统一请求入口覆盖术语、图书画像、书名、正文/目录/脚注、片段补译、语义审校、风格档案、文学润色/复核及独立繁简精校。每一次真实 HTTP/SDK 调用都有独立本地 ID；备用渠道、备用模型、格式兼容重试与响应校验重试分别记录。

1. 付费调用前提交 `in_flight` 记录，并留存已知请求价目。写入失败则不发请求。
2. 响应返回后立即记录实际模型、供应商响应 ID、结束时间及用量，再解析译文与执行质检。因此返回错误 JSON、漏译或被拒绝的响应仍被记录。
3. 超时/取消/网络错误保留待核实记录；硬终止留下 `in_flight`，不自动判定未计费。
4. 响应后费用落盘失败则停止新增付费请求；不会为了记账失败重发已付费请求。该中止由整本任务入口显式转为失败状态。
5. 完成同一记录两次不会重复累计；重复供应商响应 ID 保留证据并标记待核实，不默默重复计价。

直接调用无图书上下文的底层翻译器（例如离线单测）不建立真实订单账本。自定义付费脚本须使用 `usage_scope(job_id, attempt_id)`；图片说明修复等历史独立脚本也须显式关联图书身份，不能把无归属调用算作某个现有订单。

## Token 明细

保存输入、输出、总量、输入缓存命中/未命中及思考 Token。思考 Token 是输出明细，不能再加一次输出费用。

优先采用 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`；也支持 `prompt_tokens_details.cached_tokens`。供应商总输入已知且仅返回一侧时，可推导另一侧。两侧都缺失时保持未知；只有命中与未命中单价相同的价目可以不依赖拆分计算总费用。

对负数、布尔值、字符串计数、溢出、总量不一致、缓存明细冲突等拒绝计价。未知计数在请求明细中为 `null`；汇总数字只表示已记录部分，另提供 `tokens_complete` / `cache_tokens_complete`。

## 价格版本与供应商

内置 DeepSeek 官方价格于 **2026-09-18** 核对，从该日北京时间零点起使用；不是对更早历史价格生效时间的推断。旧订单不按当前价格回填。后续必须跟踪供应商变价并维护新版本；留存价目不是供应商账单保证。

| 模型 | 输入缓存命中 / 百万 | 输入未命中 / 百万 | 输出 / 百万 |
| --- | ---: | ---: | ---: |
| `deepseek-flash`，空闲 | CNY 0.02 | CNY 1 | CNY 4 |
| `deepseek-flash`，高峰 | CNY 0.04 | CNY 2 | CNY 8 |
| `deepseek-v4-pro`，空闲 | CNY 0.15 | CNY 4.5 | CNY 13.5 |
| `deepseek-v4-pro`，高峰 | CNY 0.30 | CNY 9 | CNY 27 |

高峰为北京时间周一至周五 09:00–12:00、14:00–18:00，其余为空闲。请求跨越峰谷或价目版本边界时，由于官方未明确该边界请求以哪个时间点计费，系统不猜测，等待账单核对。旧 Flash 别名按官方文档映射到 `deepseek-flash`，不擅自映射其他模型版本。

默认价目仅适用于 `api.deepseek.com`。阿里等渠道即使模型同名也不套用官方价，仍记录 usage，未配置价目时显示待核实。通过 `LLM_PRICING_FILE` 指定版本化 JSON 数组。每项格式如下（示意供应商，**不是阿里实际价格**）：

```json
[
  {
    "provider": "provider.example",
    "model": "exact-model-id",
    "currency": "CNY",
    "version": "provider-2026-09-18-v1",
    "valid_from": "2026-09-18T00:00:00+08:00",
    "valid_until": null,
    "cache_hit": "0.10",
    "cache_miss": "1.00",
    "output": "3.00",
    "time_policy": "fixed",
    "source": "https://provider.example/official-pricing",
    "checked_at": "2026-09-18"
  }
]
```

单价均为每百万 Token 的 Decimal 字符串。日期必须带时区。设置 `valid_until` 关闭旧版本，新版本采用新的 `valid_from`；同一有效日期出现冲突时不计价。配置文件不得包含 API Key 或客户内容。账本为每次请求留存价目快照与版本，不随后续文件修改重算已完成记录。

## 持久化与部署

新增 `llm_usage_attempts`、`llm_usage_requests` 两张表，与任务共用 `DATABASE_URL`，兼容 SQLite / PostgreSQL；默认在 `backend/epub_jobs.db`。它们独立于译文缓存，不会因重译计数重置或缓存清理而丢失。

重新部署源码不会清空账本，前提是保留相同数据库/持久卷；删除数据库、切换 `DATABASE_URL` 或用空库替换则会丢失。沿用生产任务数据库的备份策略；运行中的 SQLite 应使用备份 API 或包含 WAL 的一致性备份，不只复制主文件。两台 Mac 的本地账本不会通过 Git 同步；共享生产账本应连接同一生产后端，而不是提交数据库。

首次恢复旧任务时，如已有模型调用但该 attempt 尚未建立账本，标记历史缺口。正文计数为零但已有旧画像、术语/风格准备或未登记预分析的任务同样保留历史不确定性，不能把准备费用抹去。旧重译尝试不足的记录同样保持不完整。当前全本地缓存、没有新增模型请求的已登记 attempt 可以显示零新增请求，但不能抹去历史模型开销。

## 查询与账单导入

- 登录订单看板，可查看每本书全 attempt 的费用、缓存 Token、阶段分布、记录覆盖及账单导入金额。
- `GET /api/admin/orders/{job_id}/usage?page=1&page_size=50`：管理员会话鉴权的逐请求明细，单页最多 100 条。不会返回书稿、模型回答、原始错误、凭据或内部文件路径。
- 用户自己的 v2 任务详情在 `translation_stats.billing` 中返回汇总，不暴露逐请求响应内容。
- 旧管理费用页也采用按币种的账本汇总；旧 `cost_usd` 粗估字段仅用于兼容，不能代表实际全书费用。

需从供应商导出**请求级**原始账单，再准备匹配 JSON 数组，每行含 `ledger_id`、`response_id`、`provider`（主机名）、`amount`、`currency`。没有请求级账单时不能准确把账户总账分配给某本并发书稿。

在 backend 目录执行：

```bash
.venv/bin/python scripts/import_llm_bill.py matches.json --source-bill original-provider-bill.json
# 默认仅校验；核对后显式应用
.venv/bin/python scripts/import_llm_bill.py matches.json --source-bill original-provider-bill.json --apply
```

校验供应商与响应 ID 精确匹配、金额/币种有效，并留存原始账单 SHA-256。重导同一匹配幂等，冲突值拒绝覆盖；不按时间近似、字数或相似书名归账。原始账单真实性仍须操作者核验，文件哈希只是来源追踪，不是验签。应用按请求逐行事务提交；中途失败可幂等重跑。预分析失败且未创建订单的记录仍保留其 `job_id`，可在数据库核对，不能假定没有前期费用。
