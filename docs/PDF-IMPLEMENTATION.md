## 已实现的流程

1. 单文件 AI 翻译上传 PDF；普通转换、旧接口和批量入口仍拒绝 PDF，防止绕过确认与独立报价。
2. PDFium 在独立子进程内读取页面、文字与图片区域，检查密码、文件/页数限制、文本质量和部分复杂版面信号；限制时间、像素与 Linux 内存/CPU。所有类型统一进入逐页解析与私有中间结果：可靠原生文字直接复用，扫描/混合/疑难页使用 OCR。明确无对象的空白页、清晰短标题/页码不因文字少而单独调用 OCR；小图标不自动触发 OCR。隐藏文字、乱码/私用字形、多栏、复杂矢量与不确定坐标会转 OCR。页面来源类型与处理路线分开记录，因此多栏文本 PDF 仍显示文本型，同时注明需要 OCR。分类是保守启发式，不是已验收的版面识别模型。
3. 付款前仅做本地预检，展示开头/中间/末尾原页图，明确标记“尚未经过 OCR 验证”；**不调用任何模型**。按物理页数独立报价，保存在原订单中；用户确认后才创建支付入口。报价包含 OCR 和翻译，之后不自动补收费用。
4. 付款后，符合原始文件 200 MB / 200 页限制、已配置 MinerU、且本站已知优先额度足够时，整份原文件提交 MinerU v4 云端 API。其他新任务直接 Flash；上传前明确遭拒的请求也切换 Flash；不拆大文件绕过供应商限制。
5. MinerU 账户额度在共享磁盘 SQLite 事务中预留。使用保守滚动 24 小时窗口，不假装知道官方重置时区；密钥轮换不清零额度。外部账号消耗须由管理员先扣除，默认本站可用额度为 0。错误会短时熔断新 MinerU 提交。
6. Flash 使用固定官方地址和 `deepseek-flash`，页图 base64 输入、关闭 thinking、关闭 SDK 隐式重试。每次调用进入既有费用账本 `pdf_ocr` 阶段。输出截断按上下区域最多分两层，并缓存已成功区域；全任务有请求数上限。明确 401/402/403/429 拒绝可在条件恢复后继续，未知网络结果不自动重发。
7. 逐页文本块、物理页码、原印刷页标签、原页图片落盘为私有检查点，组装逐页章节 EPUB。页码锚点、EPUB 3 page-list 和原页图片随译文保留，图表/公式可看原图；**不承诺图片文字重绘翻译或原 PDF 布局复刻**。复用现有分块翻译、翻译检查点、交付质检、下载与通知链路。
8. 已收到响应但缺字段、内容不确定等局部问题，保存待核验页与原图，继续其他页面，并翻译已提取内容；全部页面待核验时不调用翻译。最终交付门禁阻止把未补齐的整本标为成功。账户错误、余额不足、未知网络结果与取消仍立即停止新增请求。MinerU 已接受/上传结果未知的任务，重试只查询原 batch；不能因等待超时就同时发给 Flash。远端已完成后缺失或内容结构不可靠的页面才单独交 Flash。
9. 原始文字层、分流原因和 OCR 对照结果保存在 0600 私有页检查点中。文字重合度低仅记为差异线索，不自动判定谁对谁错、不以旧文字覆盖 OCR、不追加模型重试；摘要统计保留文字层页数与差异页数，公开预检不包含原文。最终 EPUB 每页只采用一份正文，另附原页图，避免重复正文。恢复已提取页面时只补元数据，不再次付费识别；已完成 EPUB 检查点继续复用，不因新分流规则自动重跑旧任务。

**供应商边界：** Flash 仅识别本地判断需要 OCR 的页。MinerU 当前仍上传、解析整份符合限制的原文件，按原文件总页数预留额度；即使服务返回可靠文本页的 OCR 候选，也优先保留本地原文。逐页选用结果不等于 MinerU 只解析了那些页，不能据此宣称节省了相同数量的 MinerU 额度。

安全配置脚本（在目标机器使用该项目 Python 环境执行）：

```sh
python scripts/configure-pdf.py --env backend/.env --key-env-file /私有路径/mineru.env --priority-pages 800
python scripts/configure-pdf.py --env backend/.env --check
python scripts/configure-pdf.py --env backend/.env --check-mineru
```

来源文件接受 `MINERU_API_TOKEN` 或 `MINERU_API_KEY`，必须为私有普通文件。写入目标 `MINERU_API_KEY`，原配置备份到私有 `.config-backups`；保留其他配置、现有功能开关和账户标识。支持 `--stdin-key` 经加密 SSH 管道传入，禁止把真实 Key 写进命令参数或聊天。`--check-mineru` 对随机不存在任务发只读 GET，并与无效 Token 响应对照验证鉴权，不上传、不创建 OCR 任务，不能替代真实 OCR 验收。配置后仍需正常发布/重载，脚本不重启或开放 PDF。

## 安全与异常边界

- 固定 MinerU/DeepSeek API origin；CDN/上传地址只允许文档中的精确 HTTPS 域名，禁止重定向，不转发 Authorization。若供应商更换域名，应先核验再更新白名单。
- 结果包不解压路径，只读取受限大小的内容 JSON；不访问文档内图片链接或 HTML 外链。HTML 文本转义后才能进入 EPUB。
- 预览需要现有任务鉴权，不把 token 放到图片 URL，HTTP `no-store`。公开状态只含页数、进度、报价和摘要；API Key、远端签名 URL 留在服务端。
- “已识别/已提取”代表结构流程完成，不代表 OCR 语义准确率已人工验收。格式检查和模拟响应不能替代真实 OCR 质量检查。
- 未知提交结果不能自动清空 pending 检查点；应核对远端任务/账单。断网后保守停止可能需要人工协助，这是避免重复付费的明确取舍。
- 有图形而文字极少、复杂表格、嵌套 Form 或旋转文字可能保守进入 OCR；只跳过明确无对象的空白页。检测无法穷尽所有字体映射、阅读顺序与图片内文字问题；重合度也不能证明语义或顺序正确。逐页提取默认并发为 2，可用 `PDF_OCR_CONCURRENCY` 设置为 1–4；该限制按任务生效，主机总并发还取决于 Celery worker 数量。致命错误停止新请求并等待已发出请求落盘。版面精确 bbox、复杂跨页表格、页眉页脚语义去重和区域旋转矫正仍需真实语料验收与改进。

## 实测修复与人工核验（2026-09-22）

上述初期离线验证之外，现已完成真实接口对比和修复回放，详见 [实测修复报告](PDF-ACCEPTANCE-FIXES-2026-09-22.md)。新增 `content.py` 处理内容契约，`review.py` 提供有指纹、核验人和说明的缺字段审批，`scripts/regress-pdf-corpus.py` 重放私有响应，全程禁止网络。

新预检忽略没有外观内容的普通链接注释；数学字体与数学符号转 OCR。MinerU 的代码、公式、脚注、表格和图注保留，页眉页码单独记录。空的带坐标正文块标记本页与前页可能跨页合并，由 Flash 核对，不根据旧文字层猜测拆分。

独立代码与公式、正文中的 TeX 片段受到保护，图形和数学外观仍可查看原页；不承诺完整 LaTeX 可视化排版。Flash 新请求要求全部字段与段落结构；旧响应不会因提示词更新自动重发，也不在缺少依据时合并诗行或代码。

当前订单仍沿用 `failed/PARTIAL_TRANSLATION` 承载最终“待核验”状态，消息说明其余页面已处理、无需重新上传；没有新增数据库状态，也不会开放不完整译文下载。QA 的 `requires_manual_review` 与提取摘要的 `pending_pages` 明确标记原因。

审批仅支持缺少 `uncertain` 字段且其余结构合法的完整页响应，必须先核对原页与正文，再绑定响应指纹审批。明确内容不确定或损坏 JSON 不能用此脚本放行。部署后在服务器执行：

```sh
python scripts/review-pdf-page.py --work-dir backend/uploads/.pdf-work --job JOB_ID --page 4
python scripts/review-pdf-page.py --work-dir backend/uploads/.pdf-work --job JOB_ID --page 4 --approve-sha256 REVIEWED_RESPONSE_HASH --reviewer ADMIN_NAME --note '已核对原页正文与公式'
```

查询只输出指纹、页码和原因。审批保留原响应与审核记录，使派生 EPUB 清单失效；不重启任务、不调用模型。随后经既有管理员续译入口恢复。PDF 源文件和确认参数不变时，补齐一页不再改变整本检查点作用域；每段仍验证 HTML、位置、上下文与当前 QA。旧完成任务继续使用缓存，本轮未迁移生产订单。
