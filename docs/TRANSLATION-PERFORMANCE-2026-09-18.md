# 翻译卡点修复与验证边界

## 已实现

| 历史卡点 | 处理 |
|---|---|
| 两批术语请求串行耗时约 6～7 分钟 | 默认 2 个并发、硬上限 4；不削减术语候选数量 |
| 请求保持连接但长期没有最终结果 | 新增绝对请求时限，支持及时取消；不只依赖 HTTP 空闲超时 |
| 重启时重新生成术语、画像、书名、文学风格 | 在原持久化缓存数据库保存书级准备结果；只有成功完成的结果才可续用 |
| Worker 中断后靠模糊缓存命中来恢复 | 新增书级、版本化 chunk 检查点；逐块保存完成结果，续跑前重新检查当前正文/结构 QA |
| 同一批第一个坏段落阻塞其余健康段落保存 | 先保存全部健康结果，再在原 API 并发上限内并行补译失败段落 |
| 全书章节全部结束后才开始失败补译 | 每章结束即释放章节并发位并补译；所有章节共享补译并发上限 |
| 免费重译时兼容缓存逐段全表扫描 | 给 `translations.source_html` 增加索引，不清空旧缓存 |
| 重启丢失用户确认的画像/角色/策略 | 保留已确认 preflight；运行计数仍按新 attempt 清零 |
| 章节登记耗时混入补译等待，难以定位 | 增加阶段总耗时、API 并发位等待、补译等待与执行耗时、检查点复用/拒绝/存储异常计数 |

## 检查点持久化

默认继续使用 `backend/translation_cache.db`，新增 `book_translation_checkpoints` 表，不依赖临时目录，也不被 source-only 部署包覆盖。

若通过 `EPUB_TRANSLATION_CHECKPOINT_DB` 指定其他位置，需确保目录已存在、服务有读写权限，并独立纳入备份；现有部署脚本自动备份的是默认缓存数据库。

检查点按订单隔离，键包含版本、原书 SHA256、Manifest（含 HTML/locator）、预处理选项、语言、模型/供应商、质量档、用户术语和已确认设定。chunk 层还绑定实际术语表、画像、提示词命名空间、章节策略和只读上下文。准备结果中未完成的术语请求不会被当作完整术语表固化。

- `reuse` / `verified`：新 attempt 在设置一致时可恢复，但必须通过当前质检。
- `fresh`：不同 attempt 不复用；同一个 attempt 的 Worker 重启仍可恢复。
- 成功初译可恢复，但若尚未完成高质量审校/文学编辑，续跑仍要执行这些步骤。
- 已完成审校且当前 QA 仍通过的最终段落，不重复审校。
- 同一次 attempt 的失败重试计数继续，不因普通 Worker 重启重置；新的用户重译 attempt 可以重新分配失败段落预算。
- 真实请求发出前记录在途次数，含文本片段补译与提前补译队列；请求中途被打断也不会重置预算。复用成功段落时保留历史重试次数，当前请求成本计为零。
- 预处理与最终 EPUB 重打包/校验仍会执行，不缓存成品成功状态，不绕过交付门禁。
- 已交付历史文件不会自动被新代码修复；历史成品版本化修复是另一项任务。

## 参数

| 配置项 | 默认 | 说明 |
|---|---:|---|
| `EPUB_GLOSSARY_CONCURRENCY` | 2 | 术语请求并发，最大 4；账户不可用时停止排队请求并取消其他任务，已在途请求可能已发出 |
| `EPUB_GLOSSARY_REQUEST_TIMEOUT` | 300 秒 | 单次术语请求绝对时限；HTTP 空闲超时最多 60 秒 |
| `EPUB_LLM_REQUEST_WALL_TIMEOUT` | `max(180, OPENAI_REQUEST_TIMEOUT × 2)` 秒 | 正文单次真实请求绝对时限；沿用现有有界重试/质量升级策略 |
| `EPUB_TRANSLATION_CHECKPOINT_DB` | `translation_cache.db` | 可显式指定检查点数据库位置 |
| `EPUB_FAILED_CHUNK_RESCUE_CONCURRENCY` | 2 | 补译并发，仍受 `EPUB_FAILED_CHUNK_RESCUE_CONCURRENCY_CAP` 和全书 API 并发约束 |

没有盲目上调默认章节/API 并发或启用未验证的多订单限流参数。整书 2 小时软时限仍保留；检查点解决时限后重启重复工作，不把有界超时改成无限运行，也未新增无限自动重试。

排队/补译/API 耗时计数是各协程的累计值，可能互相重叠，不能直接相加当作整书耗时；整书实际耗时看 `phase_timings_ms.Total`。

## 测试

`test_d29_translation_performance.py` 纳入 backend 总回归，覆盖并发边界、账户故障/取消、绝对时限、持久化隔离、fresh 语义、当前 QA 拒绝旧坏结果、中断续跑、审校阶段隔离、失败预算、提前补译和真实原书指纹。

本次后端总回归 37/37 套通过（含专项测试 28/28 项），前端回归 132/132 项通过，部署打包与双 Mac 路径兼容测试 5/5 项通过。该测试不访问生产、不触发付款或收费翻译。

真实书稿选用已授权的《市场奇才：下一代》原文件与正式修正版：对 20 段、9 个图片混排段落的章节回放已审阅译文，续跑 20/20 段复用、0 个新模型请求；初跑和续跑输出字节一致，标签、图片、链接及属性结构与原章一致。模型响应使用替身，不代表重新调用模型翻译了整本书。

正式修正版成品另行离线复核：2681 段对齐，0 个硬失败、25 个辅助告警，正文英文残留 0、目录英文残留 0、失效目录目标 0。辅助告警不等同于已确认翻译错误，也不代表完成全书人工语言审校。

使用 `EPUB_REGRESSION_BOOK`、`EPUB_REGRESSION_SNAPSHOTS`、`EPUB_REGRESSION_TRANSLATED_BOOK`、`EPUB_REGRESSION_PREVIOUS_TRANSLATED_BOOK` 可运行选定真实书稿的现有回归。所有离线模型请求均使用受控替身。

离线并发与恢复测试只能证明调度/缓存逻辑正确，不能证明实际 DeepSeek 服务提速比例；需要部署后、经授权的整书在线测试。没有为提速降低正文、目录、媒体结构、EPUBCheck 或最终成品质检门槛。

上述记录为实现阶段的本地验证，测试没有部署代码或重新提交生产订单。发布需要先确认生产没有运行中的翻译，再按现有保留订单、缓存与成品的部署流程执行；本地测试结论不代替发布后的服务验收。
