# 真实订单恢复与模型首选修复

## 本次代码修复

- Redis 消息可见性超时默认 10800 秒，必须大于整书及普通任务硬时限；同时配置 broker、result backend 和 Celery 全局值。整书软/硬时限仍为 7200/7500 秒。
- 按任务及尝试身份获取执行租约。Redis 使用 NX、300 秒有效期、周期续期，以及所有者校验的续期/释放。Redis 不可用时不启动执行；本地无 Redis 时使用跨进程文件锁。
- 终态、未支付/未确认及过期尝试的消息不能重新执行。锁忙的 Celery 消息延后重试，避免锁持有者崩溃后的消息被提前丢弃。锁丢失时旧执行器停止，不能覆盖新所有者的状态；临时成品文件额外包含租约身份。
- `402 Insufficient Balance` 在术语阶段和正文阶段均为服务故障，不参与拆批、单段补译或文本片段补译。正文将耗尽的账户按主机及密钥指纹隔离，不能只换模型继续请求；仅已配置的独立账户可接替。
- 模型服务不可用使用 `TRANSLATION_PROVIDER_UNAVAILABLE`，缓存保留；前端显示服务暂停，不显示虚假的质检分数。服务恢复后通过复用缓存的重译入口继续，保留既有访问和重译限额检查。
- 翻译层、段落审计及成品扫描使用共享残留规则，支持带重音的拉丁姓名。缓存读取时重验，失效条目不复用，不清空整库。显式用户术语 `原文 -> 相同原文` 只允许整块精确匹配，自动生成的身份映射不能成为放行依据。
- 各质量档位首选 `deepseek-v4-flash`。切换质量档位不覆盖模型选择；显式 Pro 选择仍有效。复杂段落首轮直接升级默认关闭，审校/编辑默认使用所选主模型，失败补译可按已有预算升级 Pro。
