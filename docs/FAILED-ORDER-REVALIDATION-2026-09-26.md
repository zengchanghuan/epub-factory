## 重跑发现的付费功能验收缺口

两笔同额订单的持久化 `enable_precision_polish=true`。当前主执行器只进入转换器，未调用 `LLMPolisher`；隔离费用台账记录 0 个模型请求，结果没有精校验收记录。第一轮因此证明了格式可以通过，同时暴露了“已购买精校但仍按普通转换标成功”的缺陷。

已在本地增加 `PRECISION_POLISH_INCOMPLETE` 交付门禁：开启精校的订单必须具备精校通过证据，否则保留格式校验报告、标失败、不给成功成品和下载地址，并提示无需再次付款。此门禁不等于精校功能已补齐，也不自动退款。

补上门禁后再次用真实原文件执行：同源大书耗时 82.31 秒，正确返回 `failed / PRECISION_POLISH_INCOMPLETE`、无可交付输出；案例 C 原书耗时 14.30 秒仍为 success。两次均无模型调用。

新增专项测试覆盖此情形；本地回归 234 passed、2 skipped，另有 47 个 subtest 通过。两项跳过仍属于此前套件的指定真实书材料；本文件所列原文件转换为本次单独实际执行的验收，不计入那两个跳过项。
