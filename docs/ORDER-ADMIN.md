# 订单管理

入口 `/orders-admin.html`，独立账号默认 `tristan`。API `/api/admin/*` 只接受管理员会话，不接受普通用户登录或旧管理员查询参数密钥。现有 `/admin.html` 统计页保留，并链接到新看板。

## 首次启用

先按 `docs/DEPLOY.md` 部署源码，再在服务器的交互终端执行：

```sh
cd /home/ubuntu/epub-factory
python3 scripts/setup-admin.py --username tristan
sudo systemctl restart epub-factory
```

密码至少 6 位，不要求大小写混合或特殊符号，输入不回显；只保存带独立随机盐的 PBKDF2-SHA256 哈希（600000 次）到已有 `backend/.env`，以 0600 文件原子替换。不要在聊天、命令参数或代码中填写密码。脚本不会创建缺失的生产环境配置。修改密码后重启 API，旧会话立即失效。不需要重启翻译 worker。

管理员会话有效期 8 小时，数据库只存令牌摘要；Cookie 为 Secure、HttpOnly、SameSite Strict。生产页面必须使用 HTTPS。退出登录使服务器端会话失效。所有写操作要求同源和 CSRF token。5 分钟内单来源最多 10 次、全局最多 40 次登录尝试（正确尝试也计数）；不信任任意 forwarded-for 头，多人共用代理可能共享限额。

## 数据口径

- 范围：`epub_jobs` 中的翻译、转换和批量转换子任务。独立修复工具旧 `_repair_jobs` 内存订单不在数据库内，无法恢复历史；看板明确显示此边界。
- 列表、总数和分页只包含 2026-06-24 00:00:00 UTC 起创建的订单，并统一排除 0.01 元和 0.02 元测试订单，批量订单按整批价格判断；原始订单及详情保留。
- 可按文件名、任务 ID、商户订单号、日期（UTC）、任务状态、支付状态及订单金额筛选，默认每页 25 条。
- 订单价格为下单时的应付金额（CNY），不是收款证明。批量订单所有子任务显示整批总价，不可累计相加。未保存金额显示未知。
- 初始支付状态“未核验”。详情中的核验按钮调用支付宝只读查单并保存查询时间、金额、订单号。查询必须通过 SDK 签名校验，兼容 SDK 解包返回和完整响应；不使用异常内容绕过验签。查单失败显示未知，并不会把失败任务视为已付款。支付宝已关闭状态可能包括退款，页面不宣称具体退款金额。
- Token 费用采用现有翻译统计 `cost_usd`，以 USD 显示，明确是模型用量估算而非供应商实际账单。不使用固定汇率强行折算人民币。早期重试已覆盖的统计无法回填；未返回 usage 的计费、其他模型调用、不同提供商缓存折扣可能缺失。
- 新版本重试前保存当前费用快照，显示已知费用和已知尝试数 / 总尝试数。输入输出 Token 是本次尝试。全零的重置统计显示未知，不算免费请求。
- 源文件与结果文件下载均要求登录，路径必须位于服务的 uploads / outputs 下，禁止跨目录和外部符号链接。不存在或清理的文件返回 410；不把上传的 HTML 内联执行。

## 失败重试

只接受失败状态、有源文件、支付宝实时查询成功且金额严格匹配的任务（包括普通转换）。批量子任务核验整批订单。管理员确认可能产生新模型费用后，用数据库原子状态更新领取任务，保留原设置并复用缓存；同时点击只会入队一次。管理员可处理超过用户免费重试次数的订单；审计阶段保存账号、原错误和时间。查询支付不触发翻译、不扣费，也不自动恢复等待支付任务。

## 验证

```sh
cd backend
OPENAI_API_KEY=dummy python test_d19_order_admin.py
```

回归覆盖登录限流、会话退出/密码变更、CSRF、支付未知/金额不符/关闭、并发重试、文件路径边界、日期金额筛选、批量价格、历史费用快照和支付宝 SDK 两种响应形式。测试不调用真实支付或模型服务。新测试已加入 CI。

## 付款过程记录

新版本开始记录每笔订单首次“展示报价”“点击付款”“支付成功”的服务端接收时间，并在列表和详情显示。前两项由持有该任务访问凭据的浏览器上报；最后一项只由验签且金额匹配的支付宝回调，或管理员可信查单确认写入，浏览器不能上报成功。旧恢复/对账接口的宽松查单结果不作为成功记录来源。

数据库 `order_funnel_events` 以商户订单号和事件类型作为联合主键，重复点击/回调不会重复计数或覆盖首次时间。批量子任务共享整批过程记录。记录失败不会阻止用户打开支付宝或阻断已验证的支付处理。

“点击付款”只说明点击了站内支付宝按钮，不代表支付宝已打开、输入密码或扣款。二维码扫码无法直接检测，不推测点击记录。历史订单不补造事件；查单补充的成功时间标为查单确认时间，回调时间也是本站接收时间而非支付宝实际支付时间。无记录只能表示未知，不能据此认定用户未操作。

## 管理员测试订单

单文件和批量下单在服务端验证管理员测试密钥后，将 `is_test_order` 永久保存为 true；看板查询、总数和分页统一排除该标记，与金额无关。重试保留标记。历史日期及 0.01 / 0.02 元排除规则继续保留。普通下单不会因用户自称测试而被隐藏；请继续使用现有管理员测试模式，未带有效测试凭据的普通订单无法自动判断是否为你的测试。
