## 重复上传恢复

1. 首次上传单本和批量文件，均返回 HTTP 200。
2. 丢弃客户端持有的首次响应凭据，使用相同匿名会话的新 HTTP 客户端访问任务；未带访问令牌时返回 403。
3. 重新上传相同文件及设置，均返回 409 / `duplicate_upload`，携带原任务或批次 ID 及原访问令牌，响应为 `Cache-Control: no-store`。
4. 使用恢复的令牌读取任务，均返回 200。独立测试会话始终只有 3 个任务，重复上传没有创建额外订单。
5. 实际转换完成后再次重复上传，仍恢复原任务及原令牌。
6. 在隔离的真实 Chrome 中，仅保留该测试匿名会话和管理员测试配置，清空任务／批次凭据；从生产页面选择相同文件并点击提交。页面收到 409 后自动保存凭据、打开原任务并展示下载入口，无 403 请求、无未捕获 JavaScript 异常。

本轮直接覆盖原匿名会话丢失任务凭据的恢复场景；账户跨浏览器、已过期令牌、停用账户及被账户认领的旧匿名会话等边界，仍以对应回归测试为依据，不计入本轮线上实测范围。
