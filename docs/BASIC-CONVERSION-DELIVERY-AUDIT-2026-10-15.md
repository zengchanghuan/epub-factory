# 基础繁简转换与付款交付回归（2026-10-15）

本轮审查覆盖普通 EPUB 繁简转换、转换降级、付款校验、持久化投递、失败恢复和文件领取。历史订单、原稿及既有成品只读；验收在服务器私有临时目录使用独立数据库，不发布测试订单，不调用真实支付或模型服务。案例仅以 A/B 表示，不记录客户姓名、订单号、领取凭据或原稿路径。

## 发现与修复

| 严重程度 | 原行为与风险 | 修复 |
| --- | --- | --- |
| P1 | 核心繁简转换器处理章节抛错，被当作可跳过的清洗错误；未转换正文仍可能打包成功 | 必需的繁简转换失败立即终止，不进入降级交付；保留取消和 worker 超时的控制流 |
| P1 | 普通转换只有 EPUB 格式校验，合法的 EPUB 仍可能少正文或空段落 | 清洗前建立正文结构清单，EPUBCheck 通过后核对章节和文本单元；不完整结果不可交付 |
| P2 | 降级复用已经修改的书，可能沿用损坏正文；还会恢复默认词典配置、遗漏目录标题转换 | 从原稿重新解包，保留繁简方向、地域版本、词典开关及专名设置，同样转换目录并执行交付门禁 |
| P2 | 选中的词典缺失、为空、依赖不可用或初始化异常时静默禁用 | 明确报告转换失败，不把不符合所选配置的成品当作成功 |

正文清单兼容纯图片书：不强迫其存在正文，但仍检查原有文档存在。已有翻译任务默认仍要求非空正文清单。此门禁检测缺失/空文本单元，不声称能够识别非空段落内的一切删字或语义错误；真实样本另做逐文档规范化正文哈希、阅读顺序及二进制资源核对。

## 新增 D91 回归

`backend/test_d91_basic_delivery.py` 已加入统一 D/C 回归清单。

- 简体/繁体的 auto、台湾、香港配置以及保持原文；保护代码、SVG 和属性。
- 转换器异常、词典缺失或依赖失败、段落删除、降级前正文损坏、纯图片书及缺页。
- 取消和软超时在正文扫描期间正常传播，不被误当作成功或普通业务错误。
- 实际上传、持久化订单、模拟已验签支付事实、错误金额拒绝、队列不可用后的持久化恢复、实际转换与 EPUBCheck。
- 已付款转换失败后，通过隔离管理员身份及重新验款在同一订单恢复，领取成功，不创建第二次付款。
- 付款回调、任务投递和同浏览器重复上传的幂等性；恢复原任务访问凭据。
- 真实成品下载哈希、未授权访问拒绝、成品篡改拒绝。
- 两文件一次付款、实际转换、批量 ZIP 全员哈希、临时 ZIP 清理；缺失任何已完成成品时拒绝不完整的批量领取。

合成 EPUB 保留近期失败样本中的匿名空 `landmarks` 导航结构，不含客户正文。私有验收通过显式 JSON 清单指定原稿路径及 SHA-256，复用完全相同的付款交付用例；没有清单时明确跳过，不能用合成文件冒充真实样本。

## 验证边界

服务器只读盘点：75 笔非测试基础订单，其中 21 笔完成、54 笔待付款；查询兼容旧记录的 NULL 标志。盘点不是对全部 75 笔订单逐一重新转换或验款。

服务器最终 D91 验收：12 项测试全部通过、无跳过；其中私有样本用例包含两个 SHA 固定的真实原稿子案例。原稿哈希及两笔历史订单完整记录在验收前后均保持一致。

真实样本限两个此前失败的 EPUB 原稿。支付签名与网关响应、broker 传输为离线替身；订单状态、持久化投递、worker、转换、EPUBCheck 和下载处理使用真实代码。此轮不产生新客户支付，不核销历史订单，不跑历史翻译。PDF、MOBI、AZW3 的既有契约由原回归清单覆盖，本轮不声称新增了这些格式的真实付费样本验收。

本地 macOS 无 Java/EPUBCheck，D91 的实际 EPUBCheck 场景明确跳过，在服务器 Linux 隔离环境补验。全清单本地执行 130 个文件；3 项 Celery prefork 进程测试出现 macOS 子进程初始化异常，在 Linux 隔离环境逐项复核全部通过（每个文件 4 项测试，共 12 项），后续仍须通过容器 CI。CI 使用生产同类镜像、真实 EPUBCheck，并禁用网络；配置了 EPUBCHECK_JAR 却缺少文件时，D91 会失败而非跳过。

本文件记录修复范围与验收方法；最终 CI 和生产部署状态以该提交的 GitHub Actions 及部署验收结果为准，不将提交等同于已部署。
