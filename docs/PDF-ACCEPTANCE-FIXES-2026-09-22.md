## 修改

- PDFium：普通无外观流的 Link 注释不再让整页进入 OCR；可见注释、表单和不确定坐标仍保守处理。数学字体及数学符号单独转 OCR，覆盖本次根号映射成字母的真实案例。
- MinerU：支持 `code`、`equation`、`page_footnote`、图表标题和单元格；页眉、页码保留在私有元数据。未知结构继续显式回退，不能悄悄丢失。
- 跨页：空的带坐标正文块是本次合并行为的线索，标记本页及前页待 Flash 核对。没有猜测拆分、覆盖原页或保证识别所有跨页情况。
- Flash：区分缺置信字段、明确不确定、坏 JSON、空白矛盾、未知类型等；保存原响应，不自动重复计费。提示词要求全部字段与段落结构。局部内容错误允许继续其他页，账户/余额/未知请求异常仍停止。
- 构建与翻译：保留代码缩进、公式原始表达、脚注和单元格。行内公式在普通翻译及文字节点补救中受到保护。待核验页保留原图及明确说明，健康页可以继续翻译；全部待核验时不发翻译请求。
- 交付：最终状态、QA 和下载门禁一致；有待核验页不会标为整本成功或开放成品下载。沿用现有 `failed/PARTIAL_TRANSLATION` 枚举，消息明确“待核验、其他页检查点已保留”，并非已经新增独立的待核验订单状态。
- 恢复：提供 SHA-256 绑定的本地人工审批脚本，仅放行人工检查过的“缺字段”响应；保留原响应与审核记录。续译保持同源 PDF 的整本作用域稳定，同时逐段校验源文本、位置、上下文和当前质检，避免一页修复导致其余页的检查点整体作废。

## 验证方式

后端测试：`test_d37_pdf_pipeline.py`、`test_d37_pdf_providers.py`、`test_d37_pdf_api.py`、`test_d38_pdf_acceptance_fixes.py`。新增真实失败模式的合成回归，不把原书正文或密钥放进 Git。同步验证翻译器、代码保留、成品 QA、续译、章节组装与前端 PDF 入口。

最终通过 **123 项检查**：80 项后端 unittest、39 项既有函数式回归、4 项前端 PDF 用例。后端执行禁止网络；包含待核验页继续后续处理、全页待核验不发翻译、审批指纹失配拒绝、明确不确定不能当缺字段放行、补页后同源续译作用域不变等场景。

私有语料回放：

```sh
python scripts/regress-pdf-corpus.py --corpus-root /PRIVATE/CORPUS --output-dir /PRIVATE/REGRESSION
```

输入为上轮的 `manifest.json`、`samples/` 与 `real-evaluation/`，输出写入全新隔离目录，不修改基准响应。脚本验证 XML、原页图片保留、公式提取路线、强制 Flash 待核验页和后续页面检查点。

## 验收边界

这是提取、恢复及交付门禁修复。4 份样本及强制 Flash 待核验案例生成的 **5 份源 EPUB 均通过 EPUBCheck 5.1.0，0 错误、0 警告**；格式通过不等于待核验内容已经完整，更不等于翻译成品或 Apple Books/Kindle 全面验收。公式以保留的表达与原页核对，不承诺完整 LaTeX 排版。

正式整书翻译速度、完整成本、模型长期稳定性、低清扫描、多栏复杂表格和真实支付通知仍需后续验收。本轮没有新的收费调用，也没有重新处理生产订单。旧已完成缓存不自动重跑；旧 MinerU 缓存若缺原始内容，不会假装能够恢复被旧解析器丢弃的块。
