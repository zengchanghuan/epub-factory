## 为什么不直接打开 PDF 后缀

现有 `normalized_translation_input` 是后续最小接入点：请求准备和后台执行共用它，可沿用同一冻结身份。旧 `_pdf_to_html` 会跳过提取为空的页，并可能生成“占位内容”，因此不能作为收费交付路径。

整本 `total_chars > 0` 不能证明没有漏页；最终 EPUBCheck 也只能验证进入 EPUB 的内容，无法证明原 PDF 正文完整。先有每页明细，再做段落顺序、图片、页码映射和翻译，不能逆序放行。

## 预检合同

- `app/domain/pdf_text_preflight.py` 独立、无应用配置或数据库导入。父进程只读原文件，将有界快照存入本轮私有临时目录，记录源 SHA；不改原文件。
- 子进程以隔离 Python 启动，只用已锁定的 `pypdf==6.0.0` 解析，不载入 `.env`、API 客户端或第三方识别服务；在导入解析器前安装 Python 网络拒绝守卫。不是操作系统级安全沙箱。
- 全部页必须按原文件顺序出现且恰好一次，父进程再次校验 JSON 字段、页号、数量和统计。无部分成功、静默跳页或占位正文。
- 输出仅包括源 SHA、解析版本、页数和每页统计/标志；不返回原文、标题、原始异常或文件路径。需要密码、禁止或无法确认提取权限、损坏、超限、超时和取消必须明确失败，不能降格为空文档成功。空密码可读取且明确允许提取的权限加密文件保留诊断标志、仍需复核，不重写或解除原件权限。
- 默认 50 MiB、500 页、30 秒及字符/结果大小限制是**未用真实语料标定的工程上限**，不是产品支持规格或安全性保证；公开接入前仍需真实性能/资源消耗验证。
- 本机 macOS 实测无法设置 `RLIMIT_AS` 或 `RLIMIT_DATA`，不能冒称具备操作系统级完整内存上限。Darwin 无可用内存限制时保留 CPU/文件大小/页数/墙钟限制，输出固定 `memory_limit_unavailable` 信号，整书进入待复核；Linux 的地址空间限制或必要的 CPU/文件限制设置失败则拒绝执行。公共服务接入前仍需独立资源隔离验收。
- `text_candidate` 只表示存在可提取文字；不证明文字与视觉一致，也不证明阅读顺序、段落/表格/公式或整书覆盖可靠。所有结果固定 `eligible_for_payment=false`。
- 无字页只标记空白/图形候选并要求核对，不能自动断言它是扫描正文，也不能因为封面、插图、空白页字少就宣告整本“不支持”。有明显替换字符、控制符、私用字符或解析告警时保留待核对信号，不能自动修正原文。

可靠空白页、封面和插图的认定，以及扫描正文缺层排除，需要真实样本视觉证据；本子项不假装单靠字符统计能完成这项判断。

## 本地诊断命令

从仓库根目录执行，仅做本地分析，不上传、不付款、不翻译：

```bash
backend/.venv/bin/python scripts/inspect-text-pdf.py /absolute/path/selected-book.pdf
# 可选报告只写新文件，0600；不覆盖已有文件。
backend/.venv/bin/python scripts/inspect-text-pdf.py /absolute/path/selected-book.pdf \
  --report /private/tmp/new-text-pdf-report.json
```

诊断命令成功不代表已支持 PDF。原公共文件名/文件头检查、普通转换器和翻译适配器仍拒绝 PDF。
