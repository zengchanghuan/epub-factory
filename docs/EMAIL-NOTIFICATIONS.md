# 顾客结果邮件、商户成交提醒与离页下载

付款成功、任务已提交后，可以关闭页面，后台继续处理。重新用同一浏览器打开网站时，页面会恢复保存的任务；不要清除网站数据或使用临时/无痕窗口。邮箱为可选项，不影响下单和后台处理。

邮箱通知实现与实际发信开通是两件事。服务器尚未设置 SMTP 授权码时，页面应明确提示邮件暂不可用，不能显示“已订阅”后实际不发信。配置、部署和真实收件箱验收都完成后，才可以确认线上邮件功能可用。

商户成交提醒是独立功能：顾客是否填写邮箱、是否开启顾客结果通知，均不决定商户能否收到成交提醒。两类通知共用同一套 SMTP 发件配置，使用不同的开关与待发队列。

## 用户会收到什么

- 用户为有权访问的订单主动保存邮箱后，在任务成功、失败或取消时收到状态邮件。批量订单按文件通知。
- 邮件包含回到订单页的链接，不附带电子书，不包含书名、原始错误、服务器路径或模型凭据。
- 普通任务链接通过 URL 片段携带访问令牌；修复任务沿用现有的 128 位随机任务 ID。链接只供本人使用，请勿转发。
- 不会发送邮箱验证码或订阅验证信；邮箱格式检查不代表已验证邮箱归属。只有掌握订单访问权限的用户可查看、修改或取消订阅。
- 用户可以清空邮箱取消订阅。任务完成后才保存邮箱，也会补发当前结果通知。
- 任务文件与访问链接仍受原有保留期限约束；普通任务令牌目前为 7 天。页面不能承诺永久可下载，也不能保证所有任务隔天一定完成。

## 商户什么时候收到成交提醒

- 只有服务端验证付款成功后，才为商户生成通知。展示报价、点击付款或前端显示“支付成功”不能单独触发成交邮件。
- 默认收件邮箱是 `249998620@qq.com`。邮件包含实付金额、商户订单号、订单类型、文件数量、支付确认时间和管理员看板入口；查看看板仍须管理员登录。邮件不包含顾客邮箱、书籍正文、书名或顾客下载令牌。
- 按商户订单号去重；同一笔支付的重复回调不会重复入队。批量支付生成一封通知，测试订单默认不发。
- 收到已验证支付后立即唤醒独立派发线程尝试发送，并以 5 秒轮询兜底；不会等电子书处理完成。实际送达时间受 SMTP/QQ 邮箱服务和网络影响，不承诺零延迟。
- 不扫描并全量补发历史订单。新收到并已入队的可信支付事件会持久保存，邮件配置恢复后可以继续投递；关闭商户开关期间不会为新支付生成通知。
- 这是付款通知，不能据此判断翻译或修复已经成功。处理进度与最终结果以管理员看板为准。

## 安全配置脚本

### 在本机直接配置生产服务器

在 Mac 的交互终端、工程目录中运行：

```bash
bash scripts/configure-email-server.sh
```

此入口复用免密 SSH，把配置脚本临时传到服务器，在服务器终端隐藏输入 QQ SMTP 授权码，直接更新服务器的 `backend/.env`，随后验证 TLS 和登录。授权码不经过聊天、命令参数、本机 `.env` 或 Git。脚本不部署、不重启服务、不修改订单，默认不发送测试邮件。

配置后可以只检查连接：`bash scripts/configure-email-server.sh --check`；显式发送一封通道测试邮件到 `249998620@qq.com`：`bash scripts/configure-email-server.sh --test`。测试邮件明确标记为测试，不伪造付款事件。SMTP 接受后仍需确认收件箱收到。完成通知代码部署才会处理后续成交事件。

### 单独配置当前机器

脚本路径：`scripts/configure-email.py`。仅使用 Python 标准库，无需额外安装依赖；本机现有的 `python3` 即可运行，服务器同样适用。

在工程目录运行 QQ 预设配置：

```bash
python3 scripts/configure-email.py --qq --enable
```

QQ 预设使用已选定的客服发件邮箱 `249998620@qq.com`、`smtp.qq.com`、SSL 465 和网站根地址 `https://fixepub.com`。在终端按提示输入邮箱的 **SMTP 授权码**，不是 QQ 登录密码，见[腾讯官方邮件配置说明](https://cloud.tencent.com/document/product/1270/55456)。输入隐藏，不会输出到日志或写入命令历史。其他 QQ 发件邮箱可以显式提供 `--address`，这不会改变商户收件邮箱。

首次配置时，脚本默认设置 `OWNER_PAYMENT_EMAIL_ENABLED=1`、`OWNER_PAYMENT_EMAIL_TO=249998620@qq.com`。以后运行会保留已有商户邮箱和开关；`--owner-to owner@example.com` 可明确改为其他普通邮箱，`--enable-owner-notifications` 或 `--disable-owner-notifications` 可单独控制商户通知。`--enable` 和 `--disable` 只控制顾客结果邮件，两套开关互不影响。

例如，只关闭商户提醒，保留顾客通知和 SMTP 设置：

```bash
python3 scripts/configure-email.py --non-interactive --disable-owner-notifications
```

恢复商户提醒并明确指定收件邮箱：

```bash
python3 scripts/configure-email.py --non-interactive \
  --enable-owner-notifications --owner-to 249998620@qq.com
```

脚本默认只修改当前工程的 `backend/.env`，**不会自动同步到生产服务器，不会连接 SMTP，不会发送邮件，也不会重启服务**。如在服务器上配置，应在服务器工程目录执行相同命令。`--env /实际路径/.env` 可以指定目标文件。

文件通过临时文件原子替换，权限设为 `0600`，保留其他配置与注释。授权码不能包含换行、`${...}` 插值表达式或末尾反斜杠，以免被当前 dotenv 解析方式改变；一般邮箱授权码不含这些字符。不要提交 `.env` 或授权码。

其他服务商可用交互配置：

```bash
python3 scripts/configure-email.py \
  --host smtp.example.com --port 587 --security starttls \
  --user sender@example.com --from sender@example.com \
  --base-url https://fixepub.com --enable
```

脚本支持 SSL 465、STARTTLS 587；其他端口需显式指定 TLS 模式，不允许明文认证。网站地址必须为公网 HTTPS 根地址，不能包含账号、查询参数或片段。

自动化配置可使用 `--non-interactive --password-env 指定环境变量名`。这只从当前进程环境读取授权码；缺少显式参数或已有配置时退出，不猜测凭据。请通过安全的密钥注入方式设置该环境变量，不要把授权码直接放到命令行。切换 SMTP 主机或用户名时，不会自动复用旧授权码。

配置保存后，需要应用重新加载才会生效。应在确认没有正在处理的订单时，按项目已有发布流程完成更新，避免打断翻译。

## 验证步骤

只验证配置、TLS 连接和认证，**不保存配置、不发邮件**：

```bash
python3 scripts/configure-email.py --check
```

只有明确要发送测试信时，才运行下列命令并使用自己控制的收件箱：

```bash
python3 scripts/configure-email.py --test-to your-address@example.com
```

测试成功只表示 SMTP 服务接受邮件，还需要到收件箱或垃圾邮件目录确认。检查输出不会包含 SMTP 授权码、收发件地址或服务商原始错误响应。

无需网络的脚本回归：

```bash
python3 scripts/test_configure_email.py
```

测试使用 SMTP 替身，覆盖默认不联网、显式发信、SSL/STARTTLS 顺序、认证错误脱敏、配置原子保存、权限、旧配置保留、授权码特殊字符和不安全链接拒绝等行为。配置脚本和基础测试均不需要第三方依赖；在已安装后端依赖的 Python 环境中再运行一次，会额外验证写出的配置与真实 `python-dotenv` 加载器兼容。

完整上线验收还需要：在自己的订单中保存邮箱、关闭页面、等待任务终态、确认收件并打开链接下载。商户提醒则需要核对一笔经服务端验证的新成交与收件箱邮件；测试订单默认不触发商户提醒，不能用测试订单未发信判断异常。`--test-to` 只发送通道测试信，不会伪造付款事件。不能仅凭 `--check` 或替身测试通过宣称真实投递链路已经验收。

## 配置键

| 配置 | 说明 |
| --- | --- |
| `NOTIFY_EMAIL_ENABLED` | 顾客主动订阅的任务结果邮件：`1` 开启，`0` 关闭 |
| `OWNER_PAYMENT_EMAIL_ENABLED` | 独立商户成交提醒：`1` 开启，`0` 关闭 |
| `OWNER_PAYMENT_EMAIL_TO` | 商户成交提醒收件邮箱，默认 `249998620@qq.com` |
| `SMTP_HOST` | SMTP 主机 |
| `SMTP_PORT` | SSL 常用 `465`，STARTTLS 常用 `587` |
| `SMTP_SECURITY` | `ssl` 或 `starttls` |
| `SMTP_USER` | SMTP 认证用户名 |
| `SMTP_PASSWORD` | 隐藏输入的授权码 |
| `SMTP_FROM` | 普通发件邮箱地址；运行时未设则使用用户名 |
| `SITE_BASE_URL` | 公网 HTTPS 网站根地址；运行时兼容 `PUBLIC_BASE_URL` |
| `SMTP_TIMEOUT_SECONDS` | 单步 SMTP 超时，默认 15 秒，允许 1–60 秒 |
| `EMAIL_DISPATCH_INTERVAL_SECONDS` | 通知轮询间隔，默认 30 秒，运行时限 5–300 秒 |

## 派发、重试和限制

顾客通知订阅与待发状态保存在数据库。FastAPI 的独立后台线程定期补查订单状态、领取待发邮件，发送过程不占用整书翻译的 Celery 执行槽，也不在用户保存邮箱的 HTTP 请求中同步发信。生产环境必须继续使用持久化数据库。

同一地址重复保存不会重复入队。每个任务最多设置 3 次非空地址，最多成功发送 3 封状态通知。一次通知最多尝试 5 次，失败后按 60、120、240、480 秒延迟重试；进程退出遗留的发送租约在 600 秒后可重新领取。SMTP 不可用不会改变书籍处理结果，也不会触发额外模型调用。

SMTP 接受后、数据库记录成功前如果进程崩溃，存在重复投递的可能。稳定的 `Message-ID` 有助于收件方识别重复，但不应承诺严格只发一次。

商户支付通知使用独立持久化队列和派发线程，避免被整书翻译或顾客结果邮件拖延。每笔通知同样最多尝试 5 次，失败后按 60、120、240、480 秒延迟重试，崩溃租约在 600 秒后允许重新领取。邮件异常不能改变已验证付款结果，也不能触发额外模型调用；上述 SMTP 接受后崩溃可能重复的限制同样适用。

关闭顾客通知可保存 `--disable`，关闭商户提醒可保存 `--disable-owner-notifications`，随后按既有流程重新加载应用。关闭一种通知不会关闭另一种，订单页查询和下载仍可使用。
